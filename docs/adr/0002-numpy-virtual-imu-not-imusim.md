# Generate synthetic data with a numpy virtual IMU, not IMUSim

**Outcome (tested, `reports/synthetic_acc|imu/report.md`).** The numpy virtual IMU on LAFAN1 (99 detected fall events from 5 subjects, 7,320 ADL windows) did not improve leave-one-dataset-out results over real data plus augmentation: adding all of it changed oracle false alarms/h by +0.5 ± 5.4 (accel-only) and +5.1 ± 6.9 (accel+gyro) over 8 seeds, synthetic falls alone made it worse, synthetic pre-training followed by real training did nothing, and synthetic-only training transferred poorly (AUROC 0.89-0.92). It improved AUPRC when augmentation was off (+0.041 ± 0.007 accel-only) but never beat augmented real-only training. Keep the generator as an experiment, not as a default training input.

When synthetic data is added (after the real-only baseline), wrist accelerometer and gyroscope signals are computed from mocap by a small numpy function, not by IMUSim. The real IMUSim (`martinling/imusim`, GPL-3.0) is Python 2 code, abandoned since 2016, and only builds through the unmerged Python 3 port (PR #11) with Cython 3 and, on Python 3.14, a source patch; its default spline smoothing also produced unusable accelerations on fall motion. A finite-difference virtual IMU matched IMUSim on the one trial compared and has no licence or build burden. The PyPI package named `imusim` is an unrelated project. The bottleneck is motion data, not the simulator: the only BVH fall motion found is LAFAN1 (CC BY-NC-ND), so generated data stays out of git.
